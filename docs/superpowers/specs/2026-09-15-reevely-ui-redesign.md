## 02. 공통 디자인 시스템 (PPT p.3)

- 삭제할 느낌: 무거운 보안툴 느낌, 금색 강조 과다, 원문 나열, 버튼/배지 크기 제각각

## 12. 액션 버튼·상태값 통일 (PPT p.13) — 전역 규칙

**버튼 스타일**
- Primary: `#3E6856` 배경 + 흰색 텍스트
- Secondary: 흰 배경 + `#CAD6C7` 테두리
- Danger: 빨강/주황색, "악성으로 분류"처럼 위험 액션에만 제한적 사용
- 버튼 높이 36~40px로 통일

**상태 배지 스타일**
- 위험도: High=붉은 배지, Medium=주황/노랑 배지, Low=연녹색 배지
- 상태: 검토 필요=노랑 계열, 정상/확정=초록 계열
- 모든 배지는 둥근 pill 형태로 통일

**원문 노출 규칙 (전역 핵심 — 이후 화면별 작업에서 구현)**
- 목록/대시보드/알림에서는 원문 기본 숨김
- 노출 순서: AI 요약 → 위험 유형 → 원문 보기
- 원문 보기 클릭 시에만 전체 댓글 노출
- PDF 저장 시에는 원문·영상 URL·수집일·AI 판정 기록 포함

**버튼/상태값 문구 통일**
| 변경 전 | 변경 후 |
|---|---|
| 악성 맞음 | 악성으로 분류 |
| 아님 | 정상 댓글로 분류 |
| 상세 | 상세보기 |
| 전체 보기 | 전체 보기 → |
| 모두 읽음으로 표시 | 모두 읽음으로 표시 |
| 요주의 작성자 | 반복 위험 작성자 |
| 구독 제안 | 집중 모니터링 제안 |
| confidence 0.60 | AI 신뢰도 60% |
| 최신 댓글 업데이트 | 최근 댓글 업데이트 |

## 03. 랜딩페이지 (PPT p.4)

첫인상을 "증거 기록 서비스"가 아닌 "크리에이터 댓글 보호 서비스"로.

| 변경 전 | 변경 후 |
|---|---|
| 악플이 아니라, 기록을 남깁니다. | 좋은 크리에이터의 내일을 지킵니다 |
| 소속사도 법무팀도 없는 채널이 대부분입니다. | AI가 댓글을 먼저 읽고 위험도를 판단합니다. |
| 당신 채널의 댓글을 대신 지켜보고... | 크리에이터는 필요한 댓글만 확인하세요. |
| 시작하기 | 무료로 시작하기 / 내 채널 보호하기 |
| 구독자 1만~50만... | 혼자 댓글을 관리하는 크리에이터를 위해 만들었습니다. |

추가 지시: 상단 메뉴 = 서비스소개/요금제/고객사례/리소스, 로고 `reevely` 소문자 또는 로고 이미지 통일, CTA 버튼 `#3E6856`/hover `#1E2D26`.

## 04. 대시보드 (PPT p.5)

목적: "악플 원문 목록" → "AI가 대신 확인한 보호 성과".
- 상단 KPI 4개: 총 댓글 / 검토 필요 / 악성 비율 / 보호된 댓글
- 최근 위험 댓글: 원문 1줄 노출 금지 → AI 요약 중심
- 우측: 최근 7일 추이 + 반복 위험 작성자 TOP5

| 변경 전 | 변경 후 |
|---|---|
| 전체 플래그 | 총 댓글 |
| High/Medium/Low | 위험도 높음/보통/낮음 |
| 최근 위험 댓글 | 최근 위험 알림 |
| 요주의 작성자(누적) | 반복 위험 작성자 TOP 5 |
| 구독 제안 | 집중 모니터링 제안 |
| 이번 달 사용량·프로 플랜 | 채널 사용량 |

## 05. 댓글 목록 (PPT p.6)

목적: "원문을 읽는 표" → "필터링된 요약을 빠르게 확인하는 표".
- 상단 "원문 숨김 ON" 토글 추가
- 플랫폼 아이콘(YouTube/Instagram/TikTok) 컬럼 추가
- 긴 댓글은 표에서 말줄임, 상세보기에서만 전체 노출
- 체크박스 선택 후 일괄 조치 가능한 구조

| 변경 전 | 변경 후 |
|---|---|
| 위험도로 필터링된 댓글입니다. | AI가 분류한 댓글을 한눈에 확인하고 관리합니다. |
| 댓글 컬럼 | 댓글 내용 또는 AI 요약 |
| 상태: 확정/검토 필요 | 상태: 정상/검토 필요/검토 완료/보호됨 |
| 상세 없음 또는... | 상세보기 / 증거 보관 / 원문 보기 |
| 위험도 전체 등 필터 | 위험도·유형·상태·플랫폼·날짜 필터 |

## 06. 검토 필요 화면 (PPT p.7)

AI 확신도 낮은 댓글을 사람이 판단하기 쉽게 구조화.
- 카드 구조: 1행(위험도 배지+유형+신뢰도+날짜) / 2행(AI 요약문) / 3행(근거/태그+플랫폼) / 우측(악성으로 분류/정상 댓글로 분류/상세)

## 스코프 결정 사항 (대화 중 확정)

- 컬러 토큰 변경은 **전역 적용** — `/admin` 스태프 패널도 함께 화이트+딥그린으로 전환한다 (사용자 확정, 2026-09-15).
- 작업 순서(화면 단위, 총 12단계)는 별도 합의됨: ① 공통 디자인 시스템 → ② 대시보드 → ③ 댓글 목록 → ④ 알림 → ⑤ 검토 필요 → ⑥ 증거 보관함 → ⑦ 주간 요약 → ⑧ 요금제 → ⑨ 채널·계정 영역 → ⑩ 랜딩페이지 → ⑪ 전체 화면 재점검 → ⑫ 반응형/모바일 점검.
- 로그인이 필요한 화면(대시보드, 댓글 목록 등)은 **자동 브라우저 로그인으로 시각 검증하지 않는다** — 사용자가 직접 로그인해서 육안 확인 (사용자 확정, 2026-09-15). 공개 페이지(랜딩, `/admin/login`)만 Playwright 자동 검증 대상.
- 대시보드 "총 댓글" KPI = 악성 판정 건수가 아니라 **분석 완료된 전체 댓글 수**(`countAnalyzedCommentsByChannelId`) — "악성 비율"과 분모-비율 관계로 일관되게 (사용자 확정, 2026-09-16).
- 댓글 목록 상태값 매핑: `confirmed`→**검토 완료**, `needs_review`→**검토 필요**(유지), `reported_false`·`whitelisted`→둘 다 **정상**으로 통합 표시. `isArchived=true`면 상태 라벨과 별개로 **"보호됨"** 배지를 추가로 표시 (사용자 확정, 2026-09-16).
- 댓글 목록 체크박스 일괄 처리는 **실제 동작하는 기능으로 구현**(새 벌크 API 라우트 포함) — UI만 넣는 미봉책 아님 (사용자 확정, 2026-09-16).
- 댓글 목록 플랫폼 아이콘은 **DB에 실제 존재하는 값만**(유튜브·인스타그램) — 틱톡은 스키마에 없으므로 아이콘도 추가하지 않는다 (사용자 확정, 2026-09-16).
- 알림 탭-타입 매핑: 전체=필터 없음, **위험 알림**=`new_comment`+`video_spike`+`review_backlog`, **반복 작성자**=`repeat_author`, **공지사항**=`weekly_digest`+`reauth_required`. 계정 단위 알림(`payment_failed`/`payment_downgraded`/`analysis_quota_reached`)은 이 페이지 범위 밖 — `/mypage/subscription`에서만 노출 (사용자 확정, 2026-09-16).
- 알림 문구는 위험도·카테고리별 집계까지 확장한다 — `video_spike`는 위험도별 건수(High/Medium/Low), `repeat_author`는 카테고리별 건수(협박/인신공격 등)를 메시지에 포함 (사용자 확정, 2026-09-16, "톤/용어만 통일" 대신 "집계까지 확장"을 선택함).
- `new_comment` 알림은 원문 대신 AI 요약(`reason`)을 우선 노출한다 — 댓글 목록·대시보드와 동일한 `reason ?? text` 폴백 패턴 (사용자 확정, 2026-09-16).
- 검토 필요 화면 카드 구조: 위 "06. 검토 필요 화면" 절의 1행에 "유형"이 포함된 것으로 적혀 있지만, 실제로는 유형(category)을 3행으로 옮기고 1행은 위험도 배지+AI 신뢰도+날짜만 남기는 것으로 최종 확정한다(3행 = 카테고리 태그+플랫폼 아이콘) — "근거"라는 별도 필드가 실제 데이터에 없어서(reason이 곧 근거) 재배치함 (사용자 확정, 2026-09-16). "상세" 액션은 별도 페이지 이동이 아니라 카드를 그 자리에서 펼쳐 원문 전체를 노출하는 것이다.
- 증거 보관함의 PDF 저장 버튼은 이번 단계에서도 UI(비활성화+"준비 중")만 만들고 실제 PDF 생성 로직은 만들지 않는다(사용자 확정, 2026-09-16) — CLAUDE.md "만들지 않는 것" 목록과 일치. "삭제" 버튼은 기존 "보관 해제"(unarchive)와 동일한 동작이며 댓글을 영구 삭제하지 않는다.
